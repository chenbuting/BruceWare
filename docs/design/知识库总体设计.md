# 知识库总体设计

通用个人知识库，不绑招标。可建多个库。先整理再问。四层彼此独立，可开关。

## 一句话

多库隔开。有范围再收窄路径。Wiki 默认关。向量找原文原图。结论带出处。

## 要解决什么

- 资料要能分类、换电脑还能认
- 以后能问，对错能对回原件
- 摘要可沉淀，但不是每次必走，关掉就不养
- 路径可收窄，也可按条件关掉，改走整库向量

## 四层（彼此独立）

| 层 | 作用 | 开关 |
|---|---|---|
| 知识库 | 最大隔间，避免串台 | 默认只查当前库；跨库以后再加 |
| 路径 / 标签 | 缩小到某个文件夹、标签 | 有范围才收。也可关，改整库向量搜 |
| Wiki 摘要 | 沉淀笔记、指路 | 默认关。关掉不影响路径，也不胀 |
| 向量 + RAG | 换说法找到原文原图，带出处 | 后期查内容时用 |

Wiki 关了，路径照常。路径关了，仍在当前库里正常向量查。

常用组合：

1. 开路径 + 关 Wiki（默认就合适）
2. 路径、Wiki 都关，只向量
3. 都开：先收窄，摘要可指路，再向量补

## 流程

**入库**

进某个库 → 原件（上传，或以后引用文件柜）→ 你确认目录/标签（可建议，不自动扔）→ 原文进向量。Wiki 开着才可选写摘要。

**提问**

当前库 → 路径若开着且有范围就收窄 → Wiki 若开着可指路 → 向量找原文原图 → 结论 + 依据。

## 回不回原文

不写死关键词。长期规则 + 资料打标 + 当次覆盖。默认带出处。吃不准回原件。可设两个预设：严格出处 / 宽松概述。

## Wiki

- 默认可关。关掉没有胀、假、要养的问题
- 开了：点了才沉淀；过期、上限自动管
- 多库只能减轻单个库的量，不能代替「默认关、不猛写」

## 图文

后期按一等公民做：抽图、OCR、检索能出图、须原图带原图。整套材料组后做。不是做不到。

## 文件放哪

- 物理位置：`根目录/BruceWare/kb/{库id}/`（未「跟着走」时用程序 `data/kb/`）
- 库里只存相对路径，不写盘符
- 文件柜里已有的：只引用、不拷第二份（一期先上传，引用字段占位）
- 整包拷走、向量模型不变：不重算向量
- 新电脑要再指定一次根目录

## 短处怎么收

- Wiki 要养：默认关；开了才写、自动瘦
- 图文：后期做齐，不整包搬别的项目
- 办事（搜网、改文件）：库只管家，用到再调工具
- 懒得写规则：默认带出处 + 两个预设

## 分期

| 期 | 做什么 |
|---|---|
| 一期 | 多库、上传、文件夹、标签、预览 |
| 二期 | 对着当前库提问（先关键词），带出处 |
| 三期 | 可选 Wiki + 白话规则 + 当次覆盖 |
| 四期 | 向量 + 图文检索 |

## 先不做

自动分目录、多机同步、招标专活、改衣橱和文件柜已有逻辑。
